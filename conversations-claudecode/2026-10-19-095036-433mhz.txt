
> Can you please generate an ESPhome configuration for an ESP32-H2 (on zigbee)
  to be able to send and receive 433mhz signals for my door chime? Please also
  recommend some consumer-accessible components for the radio communication,
  and provide the recommended pinout for those components.

  Thought for 31s (ctrl+o to expand)

● Important Hardware Caveat First

  The ESP32-H2 has no WiFi — it's exclusively Zigbee/Thread/BLE (IEEE 802.15.4).
  This means ESPHome on the H2 communicates back to Home Assistant only via
  Zigbee (through ZHA or Zigbee2MQTT), not the native API. ESPHome's Zigbee
  support for H2 is also still experimental. If you need WiFi + Zigbee bridging,
  an ESP32-C6 or a separate coordinator is a better fit. That said, the H2
  works well as a pure Zigbee end device.

  Recommended 433MHz Components

  The RXB6 + FS1000A combo is widely stocked on Amazon, AliExpress, and

  Pinout

  RXB6 Receiver → ESP32-H2

  ┌────────────┬──────────────┐
  │  RXB6 Pin  │ ESP32-H2 Pin │
  ├────────────┼──────────────┤
  │ VCC        │ 3.3V         │
  ├────────────┼──────────────┤
  │ GND        │ GND          │
  ├────────────┼──────────────┤
  │ DATA (OUT) │ GPIO4        │
  ├────────────┼──────────────┤
  │ ANT        │ 17.3cm wire  │
  └────────────┴──────────────┘

  FS1000A Transmitter → ESP32-H2

  ┌─────────────┬──────────────────────────────────────────┐
  │ FS1000A Pin │               ESP32-H2 Pin               │
  ├─────────────┼──────────────────────────────────────────┤
  │ VCC         │ 3.3V (or 5V for better range — see note) │
  ├─────────────┼──────────────────────────────────────────┤
  │ GND         │ GND                                      │
  ├─────────────┼──────────────────────────────────────────┤
  │ DATA (ATAD) │ GPIO5                                    │
  ├─────────────┼──────────────────────────────────────────┤
  │ ANT         │ 17.3cm wire                              │
  └─────────────┴──────────────────────────────────────────┘

  ▎ Note: FS1000A transmit range roughly doubles at 5V. If you power VCC from
  ▎ 5V, the DATA pin is driven by ESP32-H2 GPIO at 3.3V — this is fine since the
  ▎ FS1000A DATA input has a threshold well below 3.3V.

  ESPHome Configuration

  esphome:
    name: door-chime-rf
    friendly_name: Door Chime RF Bridge

  esp32:
    board: esp32-h2-devkitm-1
    variant: esp32h2
    framework:
      type: esp-idf
      version: recommended

  logger:
    level: DEBUG  # Set to INFO after your RF codes are confirmed

  # Zigbee end device — pairs with ZHA or Zigbee2MQTT
  zigbee:
    type: end_device

  # ──────────────────────────────────────────
  #  433MHz Receiver (RXB6 → GPIO4)
  # ──────────────────────────────────────────
  remote_receiver:
    id: rf_rx
    pin:
      number: GPIO4
      mode:
        input: true
    # Dump ALL received codes to the log so you can discover your doorbell code.
    # Comment out dump: after you've captured your codes.
    dump: rc_switch
    tolerance: 60%
    filter: 250us
    idle: 4ms

  # ──────────────────────────────────────────
  #  433MHz Transmitter (FS1000A → GPIO5)
  # ──────────────────────────────────────────
  remote_transmitter:
    id: rf_tx
    pin: GPIO5
    carrier_duty_percent: 100%  # RF (not IR) uses no carrier modulation

  # ──────────────────────────────────────────
  #  Doorbell binary sensor (Zigbee IAS Zone)
  # ──────────────────────────────────────────
  binary_sensor:
    - platform: remote_receiver
      id: doorbell_button
      name: "Doorbell"
      device_class: occupancy  # or "door" — controls Zigbee cluster type
      rc_switch_raw:
        # Replace with your actual doorbell code discovered via dump: above.
        # Example: code "101010101010101010101010" protocol 1
        code: "101010101010101010101010"
        protocol: 1
      filters:
        - delayed_off: 3s  # Debounce: ignore repeats within 3 seconds

  # ──────────────────────────────────────────
  #  Chime trigger button (Zigbee On/Off cluster)
  # ──────────────────────────────────────────
  button:
    - platform: template
      name: "Ring Chime"
      on_press:
        - repeat:
            count: 3
            sequence:
              - remote_transmitter.transmit_rc_switch_raw:
                  transmitter_id: rf_tx
                  # Replace with your chime's RF code
                  code: "101010101010101010101010"
                  protocol: 1
              - delay: 10ms

  ---

  Step-by-Step Setup

  1. Flash with dump: rc_switch enabled and open the ESPHome log viewer.
  2. Press your doorbell button — the log will print lines like:
  [RCSwitchRawAction] Raw: protocol=1 data=010101... (24 bits)
  3. Copy that code into the rc_switch_raw block for both the binary sensor and
     button.
  4. Pair the device with your Zigbee coordinator (ZHA/Zigbee2MQTT) — it will
     appear as a sensor + button device.
  5. Once confirmed, remove or comment out dump: rc_switch to reduce log noise.

  ---

  Limitations to Keep in Mind

  - No OTA updates via WiFi — flash subsequent updates via USB or ESPHome's
    Zigbee OTA (experimental).
  - ESPHome Zigbee is experimental — check the ESPHome Zigbee docs
    (https://esphome.io/components/zigbee.html) for your ESPHome version before
    flashing.
  - Multi-protocol chimes (e.g., HomeEasy, PT2262-based) may need protocol: 2 or
    protocol: 6 — try different values if the chime doesn't respond.

> How can I configure and use this set up to determine the RF code for my
  existing door chime, so that home assistant can either know when the door
  chime has been pressed, or home assistant itself can cause the ESP32-H2
  circuit to transmit an RF code and trigger the door chime.

  Thought for 18s (ctrl+o to expand)

● Overview

  Your doorbell system has two RF devices:
  - Push button (outside) — transmits a fixed code when pressed
  - Chime unit (inside) — plays when it receives that code

  Your ESP32-H2 needs to learn that code once, then it can do both jobs: detect
  presses and replay the code on demand.

  ---

  Phase 1: Capture the Code (via USB Serial)

  Since the ESP32-H2 has no WiFi, you can't use the ESPHome web dashboard for
  logs. Connect it via USB instead.

  1. Flash the config from the previous response as-is — dump: rc_switch is
  already enabled.

  2. Open a serial terminal at 115200 baud. From the ESPHome CLI:

  # Linux / macOS
  esphome logs door-chime-rf.yaml --device /dev/ttyUSB0

  # Windows (find COM port in Device Manager first)
  esphome logs door-chime-rf.yaml --device COM3

  Or use PuTTY / any serial terminal at 115200 baud.

  3. Press your doorbell button 3–5 times. Watch the log output. You'll see
  lines like:

  [D][remote.rc_switch]: Received RCSwitch Raw: protocol=1
  data="010110100101101001011010" (24 bits)
  [D][remote.rc_switch]: Received RCSwitch Raw: protocol=1
  data="010110100101101001011010" (24 bits)

  The code repeating consistently across multiple presses confirms it's the
  right one. Note:
  - data — the bit string to copy
  - protocol — the number (usually 1–6 for common doorbells)
  - bit count (24 is most common for PT2262-based units)

  ▎ If you see nothing: Try holding the button longer, reduce filter: to 100us,
  ▎ and make sure the RXB6 antenna wire is attached. Some units use protocol 2
  ▎ or 6 — the dumper tries all of them automatically.

  ---

  Phase 2: Update the Config

  Replace the placeholder codes with your captured values. Only two places need
  updating:

  binary_sensor:
    - platform: remote_receiver
      id: doorbell_button
      name: "Doorbell"
      device_class: occupancy
      rc_switch_raw:
        code: "010110100101101001011010"   # ← your captured data
        protocol: 1                         # ← your captured protocol
      filters:
        - delayed_off: 3s

  button:
    - platform: template
      name: "Ring Chime"
      on_press:
        - repeat:
            count: 3
            sequence:
              - remote_transmitter.transmit_rc_switch_raw:
                  transmitter_id: rf_tx
                  code: "010110100101101001011010"   # ← same code
                  protocol: 1                         # ← same protocol
              - delay: 10ms

  Then comment out dump: rc_switch so the log isn't flooded on every press:

  remote_receiver:
    id: rf_rx
    pin:
      number: GPIO4
      mode:
        input: true
    # dump: rc_switch   ← comment out after code is confirmed
    tolerance: 60%
    filter: 250us
    idle: 4ms

  Reflash via USB.

  ---

  Phase 3: Pair with Home Assistant

  If using ZHA:
  1. In HA → Settings → Devices & Services → ZHA → Add Device
  2. Power-cycle the ESP32-H2 (or press its reset button) to trigger pairing
     mode
  3. It will appear as a new Zigbee device with a sensor and button entity

  If using Zigbee2MQTT:
  1. Enable join in the Z2M dashboard
  2. Power-cycle the ESP32-H2
  3. It will appear in the Z2M device list; approve and rename it

  ---

  Phase 4: Use It in Home Assistant

  After pairing, two entities appear in HA:

  ┌────────────────────────┬────────────┬───────────────────────────────────┐
  │         Entity         │    Type    │           What it does            │
  ├────────────────────────┼────────────┼───────────────────────────────────┤
  │ binary_sensor.doorbell │ Binary     │ Turns on briefly when button is   │
  │                        │ sensor     │ pressed                           │
  ├────────────────────────┼────────────┼───────────────────────────────────┤
  │ button.ring_chime      │ Button     │ Pressing it transmits the RF code │
  │                        │            │  to ring the chime                │
  └────────────────────────┴────────────┴───────────────────────────────────┘

  Automation: Notify when doorbell pressed

  automation:
    - alias: "Doorbell pressed notification"
      trigger:
        - platform: state
          entity_id: binary_sensor.doorbell
          to: "on"
      action:
        - service: notify.mobile_app_your_phone
          data:
            title: "Doorbell"
            message: "Someone is at the door"

  Automation: Ring chime from HA (e.g. on another trigger)

  automation:
    - alias: "Ring chime from script"
      trigger:
        - platform: ...   # whatever you want
      action:
        - service: button.press
          target:
            entity_id: button.ring_chime

  Troubleshooting Tips

  ┌─────────────────────┬──────────────────┬───────────────────────────────┐
  │       Problem       │   Likely cause   │              Fix              │
  ├─────────────────────┼──────────────────┼───────────────────────────────┤
  │ Chime doesn't ring  │ Wrong code or    │ Re-sniff; try repeat: count:  │
  │ when button is      │ protocol         │ 5                             │
  │ pressed in HA       │                  │                               │
  ├─────────────────────┼──────────────────┼───────────────────────────────┤
  │ Binary sensor       │                  │ Add a second rc_switch_raw    │
  │ triggers on         │ Code collision   │ condition or use rc_switch    │
  │ neighbours' devices │                  │ with address/command fields   │
  ├─────────────────────┼──────────────────┼───────────────────────────────┤
  │                     │ Rolling-code     │ These can't be replayed —     │
  │ Code changes each   │ chime (rare on   │ you'd need to intercept the   │
  │ press               │ 433MHz)          │ button's wires directly       │
  │                     │                  │ instead                       │
  ├─────────────────────┼──────────────────┼───────────────────────────────┤
  │ Inconsistent        │ Antenna missing  │ Ensure the 17.3cm wire is     │
  │ detection           │ or marginal      │ soldered; move closer for     │
  │                     │                  │ testing                       │
  └─────────────────────┴──────────────────┴───────────────────────────────┘

  Most consumer 433MHz doorbells (Friedland, Byron, Kerui, generic Amazon units)
  use static PT2262 codes on protocol 1 — the process above works for nearly
  all of them.
